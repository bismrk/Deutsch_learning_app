# Гайд із тестування (Testing Guidelines)

Цей документ описує правила написання та запуску тестів для модулів `backend/`, `bot/` та `miniapp/`.

## Інструменти та запуск

- **Backend (`backend/`):** `pytest`, `pytest-asyncio`, `httpx.AsyncClient`, `respx`.
  - Увесь набір: `uv run pytest`
  - Один файл: `uv run pytest tests/test_health.py`
- **Bot (`bot/`):** `pytest`, `pytest-asyncio`, `respx` (для моків викликів Backend API).
  - Увесь набір: `uv run pytest`
- **Mini App (`miniapp/`):** перевірка типів і виробничої збірки через `npm run build` (та юніт-тести компонентів/теми за наявності).

## Обов'язкові правила

1. **Жодних реальних мережевих запитів у тестах:** виклики до DeepSeek API, Google Sheets та Telegram Bot API завжди мокаються через `respx` або FastAPI `dependency_overrides`.
2. **Ізоляція БД:** інтеграційні тести `backend/` працюють із тестовою PostgreSQL БД (або транзакційним rollback після кожного тесту) — ніколи не тестуй на продакшен-даних і не заміняй Postgres на SQLite там, де перевіряються `JSONB`, функціональні індекси чи міграції Alembic.
3. **Детермінованість часу:** тести FSRS (`due_at`), `consistency_score`, `auth_date` і задач `scheduler` використовують фіксовані UTC/IANA-мітки часу замість системного `datetime.now()`.
4. **Незалежність `bot/`:** тести `bot/` не повинні імпортувати код із `backend/` — взаємодія перевіряється лише через HTTP-контракт `api_client.py`.

## Критичні інваріанти, які завжди покриваємо тестами

- **Ізоляція по `user_id`:** користувач A не може читати, змінювати чи видаляти слова, сесії або статистику користувача B.
- **Авторизація:** валідний і підроблений HMAC-SHA256 `Telegram initData`, прострочений `auth_date` (> 24 год), невірний `X-Internal-API-Key`.
- **Античит підказок:** при `used_hint = True` рейтинг FSRS на бекенді завжди обмежується `min(rating, 2)` (`Hard`).
- **Стійкість LLM:** валідний JSON, невалідний JSON → 1 retry, помилка 429/таймаут → `tenacity` backoff, перевищення `daily_llm_calls` → HTTP 429 і коректне скидання при зміні `llm_calls_reset_date`.
- **Формули спайдерплоту (`scoring.py`):** порожня БД (0 балів), вагові коефіцієнти `A1=0.35`, `A2=0.70`, `B1=1.0`, фактор покриття тем (`coverage_factor`) і штрафи за прострочені > 24 год слова.
- **Ідемпотентність планувальника:** повторний запуск тижневого звіту в межах того самого `week_start` не створює дублікатів у `weekly_snapshots`.
